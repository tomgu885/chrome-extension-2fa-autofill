# 本地验证器 · Local Authenticator

在 Chrome 中管理 TOTP 两步验证码，支持自动填充、二维码导入、加密备份和可选的加密同步。

**全部功能免费开放，无需注册、购买许可证或安装手机配套应用。通过 Chrome 开发者模式安装，无需 Chrome Web Store。** 本项目独立实现，不是原商店扩展的修改版。

## 安装

需要桌面版 **Chrome 120 或更新版本**。安装后，扩展在当前 Chrome 用户资料中保存账号。

### 方式一：使用已构建的安装包

无需在本机安装 Node.js 或 Git，可以直接下载 GitHub 构建的安装包：

1. 打开仓库的 [GitHub Actions 打包页面](https://github.com/tomgu885/chrome-extension-2fa-autofill/actions/workflows/package.yml)。
2. 选择最近一次成功的 **Package Chrome extension** 运行，核对分支和提交。
3. 在运行详情底部的 **Artifacts** 区域，下载 `local-authenticator-1.0.0.zip`（名称随版本变化）。下载需要登录 GitHub，构建产物保留 30 天。
4. 下载后按下面步骤安装。如果没有可用安装包，仓库有写入权限的用户可点击 **Run workflow**，选择分支后启动打包；普通用户也可按方式二自行构建。

如果你已从其他途径获得同样的已构建安装包，也可以直接安装：

1. 将安装包解压到一个准备长期保留的文件夹。
2. 在 Chrome 地址栏输入 `chrome://extensions` 并打开。
3. 打开右上角的「开发者模式」。
4. 点击「加载已解压的扩展程序」，选择解压后**直接包含 `manifest.json`** 的文件夹。
5. 点击 Chrome 工具栏的拼图图标，将「本地验证器」固定到工具栏。
6. 点击扩展图标，即可添加或导入账号。

请保留解压后的文件夹，Chrome 会从这里读取扩展文件。安装步骤的简版见 [INSTALL.md](INSTALL.md)。

### 方式二：从本仓库构建

如果只有仓库源码，需要先安装 **Node.js 22+（包含 npm）**。使用 Git 获取源码并构建：

```sh
git clone https://github.com/tomgu885/chrome-extension-2fa-autofill.git
cd chrome-extension-2fa-autofill
npm ci
npm run build
```

也可以在 GitHub 仓库点击 **Code → Download ZIP** 下载源码，解压后在包含 `package.json` 的目录打开终端，执行 `npm ci` 和 `npm run build`。

构建成功后，按方式一的第 2–5 步操作，但加载的文件夹应为仓库内的 **`dist/`**。仓库根目录和 `src/` 不是可直接加载的安装目录。

如需生成可分发的安装包：

```sh
npm run package
```

输出文件为 `artifacts/local-authenticator-1.0.0.zip`。**GitHub 的 Download ZIP 是源码包，与这个已构建安装包不同；源码需要构建后才能安装。** 打包命令需要系统提供 `zip`；没有该命令时仍可直接加载 `dist/`，或手动压缩其中的文件。

### 通过 GitHub 自动打包

仓库提供 [`.github/workflows/package.yml`](.github/workflows/package.yml)：修改扩展源码、构建脚本、测试、依赖、类型检查配置或安装说明并推送时自动运行，也可在 Actions 页面手动点击 **Run workflow**。

流程依次安装依赖、执行核心测试与类型检查、构建扩展、在隔离的无头 Chromium 中执行端到端测试，全部通过后生成并上传可安装 ZIP。打包名称从 `package.json` 读取版本，并检查它与构建后的 `manifest.json` 一致。安装包直接包含 `manifest.json` 等文件，解压一次即可加载。

GitHub 执行构建和测试，无需 Chrome Web Store 发布，也无需配置任何账号密钥或 Secrets。工作流仅申请仓库内容读取权限，安装包通过 Actions Artifacts 下载。

## 使用

### 1. 添加第一个账号

1. 在需要启用两步验证的网站，进入安全设置，选择「身份验证器应用」或类似选项。
2. 在网站提供二维码或设置密钥时，打开本扩展。
3. 点击「＋ 添加」，填写以下信息后点击「保存账号」。

| 字段 | 如何填写 |
| --- | --- |
| 服务名称 | 方便识别的名称，例如 `GitHub`。 |
| 用户名 / 邮箱 | 实际登录用户名或邮箱；自动填充会使用它来匹配账号。 |
| TOTP 密钥 | 网站提供的 Base32 设置密钥，不是登录密码或当前的 6 位验证码。 |
| 登录网站 | 实际出现验证码输入框的完整主机名，例如 `github.com`；多个主机名用逗号分隔。 |
| 文件夹、标签 | 可选，用于区分个人、工作或不同客户的账号。 |

多数网站使用默认的 SHA1、6 位、30 秒周期；只有网站明确提供其他参数时，才调整「高级 TOTP 参数」。

保存后，点击账号卡片上的验证码即可复制，并粘贴到网站完成两步验证设置。网站提供的恢复码也应另行妥善保存。

### 2. 从二维码或链接导入

打开扩展的「导入」页，任选一种方式：

- **二维码图片**：点击「选择二维码图片」，上传 PNG、JPG 或 WebP；支持多选。
- **网页二维码**：让二维码完整显示在当前网页中，在二维码上点右键，选择「添加此处的 2FA 二维码」。扩展会本地扫描当前可见画面并打开导入预览。
- **TOTP 链接**：粘贴 `otpauth://totp/…` 链接，点击「读取链接」；多个链接每行一条。
- **Google Authenticator 迁移**：在 Google Authenticator 中使用导出/转移账号功能取得迁移二维码，再上传二维码图片或粘贴 `otpauth-migration://offline?data=…` 链接。如果一个批次有多张二维码，需全部添加，按钮才会允许确认导入。

核对待导入账号，可填写统一的文件夹和登录网站，然后点击「确认导入」。导入会保留已有账号并跳过重复项。二维码和迁移链接包含账号密钥，请勿发到公开网站或在线扫码服务。

二维码在本机解析。网页右键扫描只处理可见区域；二维码被遮挡、未显示完整或过小时，可滚动/放大页面后重试，或上传清晰的二维码图片。

### 3. 开启自动填充

自动填充需要同时完成**账号网站配置**和**网站授权**：

1. 在账号卡片点击「编辑」，在「登录网站」填写验证码页面的完整主机名。
2. 在 Chrome 中打开该网站，通过工具栏图标打开扩展。
3. 确认「当前网站」显示正确，点击「启用填充」，接受 Chrome 的该站点权限提示。
4. 在「设置」中确认「自动填充验证码」已开启，然后回到网站登录。
5. 页面出现验证码输入框且账号唯一匹配时，扩展会自动填入验证码。你仍需自行点击网站的登录/验证按钮。

例如：验证码页面为 `https://login.example.com/verify`，账号的登录网站填写 `login.example.com`，用户名填写实际登录时的用户名。不要填写整个 URL、邮箱域名、通配符或仅填写 `example.com` 来代替子域名。

默认同时匹配主机名和用户名。同一网站配置多个账号时，扩展不会随意选择。对于同源、同标签页的分步登录，扩展会临时记住前一步输入的用户名，最长 10 分钟。

如果验证码页面确实没有可识别的用户名，可编辑对应账号，显式勾选「页面无用户名时，允许单账号匹配填充」。仍然存在多个候选账号时不会填充。扩展不覆盖手动输入的内容；无法匹配时可以点击卡片复制验证码。

### 4. 整理账号

- 搜索框可搜索服务名称、用户名、文件夹、标签或网站；按 `/` 可快速聚焦搜索框。
- 编辑账号填写文件夹后，账号列表上方会出现对应筛选按钮。
- 点击卡片上的星标可置顶；点击「★ 置顶」可只查看置顶账号。
- 点击「编辑」修改账号；点击「删除」并确认后移除账号。
- 点击扩展右上角的 `↗`，可在独立标签页中使用完整管理界面。

### 5. 导出和恢复加密备份

**导出：**

1. 打开「备份与同步」。
2. 在「加密备份」中输入至少 12 个字符的独立口令，再次输入确认。
3. 点击「导出加密备份」，保存下载的 JSON 文件。

**恢复：**

1. 在同一页的「恢复已有备份」区域选择加密 JSON 文件。
2. 输入导出时使用的备份口令。
3. 点击「解密并合并账号」。

恢复会保留本地账号并跳过重复项，既有账号的文件夹等信息以本地为准。口令错误或文件损坏时不会写入账号。口令无法找回；备份仅支持本项目的 v1 格式，不保证兼容其他验证器的加密备份文件。

### 6. 在多台设备间加密同步（可选）

**同步采用手动快照上传和拉取，不会在后台实时同步。** 不使用同步也能使用其余全部功能。

准备：在两台设备安装本扩展的相同版本，以同一 Chrome 账号登录并开启扩展同步。同步口令应在两台设备上保持一致，可以与备份文件口令不同。

1. **第一台设备**：打开「备份与同步」，输入至少 12 个字符的同步口令，点击「创建 / 解锁同步」。首次创建会上传当前账号库的加密快照。
2. **另一台设备**：等待 Chrome 同步数据到达，输入相同口令并解锁，然后点击「拉取并合并」。如果提示没有云端数据，请先检查 Chrome 同步设置并稍后重试，避免提前创建另一个快照。
3. **后续更新**：修改账号后，在修改设备上点击「上传本地快照」；在其他设备点击「拉取并合并」。多台设备都修改了账号时，先拉取合并再上传。
4. 不再使用时点击「锁定」。重启浏览器或重新加载扩展后，也需要重新输入同步口令。

拉取只合并账号，不传播删除，也不覆盖已有账号的信息。Chrome Sync 空间约 100 KB；较大的账号库请使用加密备份文件迁移。实际跨设备传送依赖 Chrome 同步服务和浏览器策略。

### 7. 更新扩展

1. 先导出加密备份。
2. 源码安装时，在仓库目录执行 `git pull --ff-only`、`npm ci` 和 `npm run build`；安装包安装时，将新版文件覆盖到原来的解压目录。
3. 打开 `chrome://extensions`，点击本扩展卡片上的重新加载按钮。
4. 刷新需要自动填充的网站；如需同步，重新解锁同步。

保持原来的安装目录，不必先卸载扩展。卸载会移除该 Chrome 用户资料中的本地账号；换电脑或切换用户资料时，请通过备份或同步迁移。

## 常见问题

| 问题 | 处理方式 |
| --- | --- |
| 加载时提示找不到或无法读取 manifest | 安装包应选择直接包含 `manifest.json` 的文件夹；源码应先构建，再选择 `dist/`。不要直接选择 ZIP。 |
| 从 GitHub 下载后没有 `dist/` | GitHub 的源码包不含构建产物，请按方式二执行 `npm ci` 和 `npm run build`。 |
| 「启用填充」按钮不可用 | 在普通 HTTP/HTTPS 登录网站中，从工具栏打开扩展；Chrome 内置页面和扩展自身管理页不能作为授权目标。 |
| 已授权，仍未填充 | 检查「设置」开关、验证码页面的精确主机名、用户名及是否有多个候选账号；刷新网站后重试。特殊自定义控件可手动复制。 |
| 网站提示验证码错误 | 检查电脑日期、时间和时区设置，确认密钥、算法、位数、周期与网站一致，并使用当前有效的验证码。 |
| 二维码无法识别 | 确认是 TOTP 或 Google 迁移二维码，图片完整清晰；普通链接、支付二维码和 HOTP 不受支持。 |
| 同步提示云端已有新版本 | 先「拉取并合并」核对账号，再上传本地快照。 |
| 同步提示容量超限 | 本地账号仍可使用，改用加密备份在设备间迁移。 |
| 忘记备份/同步口令 | 无法找回口令。若本地账号仍可访问，可导出使用新口令的备份；备份口令更改不等于同步口令更改。 |

## 隐私与数据

- 验证码在本机生成，无遥测、广告、账号注册或许可证校验；没有自建后端或远程代码。
- **本地密钥以明文保存在 Chrome 本地扩展存储中，不另设本地口令锁。** 加密保护适用于导出的备份和上传的同步快照。请保管好设备和浏览器用户资料。
- 站点访问按需授权，可到「设置 → 已授权的网站」移除权限。
- 备份与同步使用 AES-256-GCM 和口令派生密钥；Chrome Sync 接收的是加密数据，不是明文密钥或口令。
- **卸载扩展前请先备份。** 本地账号不会自动存到其他 Chrome 用户资料或其他设备中。

## 功能

- 不设账号数量上限；生成和复制 SHA1 / SHA256 / SHA512、6 / 8 位 TOTP；支持 5–300 秒周期。
- 增删改账号；搜索、文件夹、标签、置顶。
- 本地解析二维码图片、`otpauth://totp` 链接和 Google Authenticator protobuf 迁移二维码，支持多张迁移批次完整性检查与去重。
- 网页右键扫描可见区域中的二维码，包括 canvas 与跨域图片；导入前展示账号确认。不主动获取图片 URL。
- 按完整主机名和用户名自动匹配，识别动态表单和分格验证码；支持同源分步登录的临时用户名记忆。不自动提交、不覆盖手动输入。默认禁用无用户名匹配，可按账号开启。
- AES-256-GCM 加密备份、导入合并。PBKDF2-SHA256 / 600,000 次迭代，随机 16 字节盐及 12 字节 IV。
- 可选 Chrome Sync：口令加密、分块存储、手动快照上传和拉取合并；会话锁定；不上传明文账号或口令。

## 开发与验证

开发环境需要 Node.js 22+、npm。以下命令在仓库根目录执行：

```sh
npm ci
npm test
npm run check
npm run build
```

使用已构建的 `dist/` 加载扩展。端到端测试和界面演示命令：

```sh
npx playwright install chromium
npm run test:e2e
npm run preview
```

`npm run preview` 会在 `http://127.0.0.1:43817` 启动界面演示，仅使用公开测试密钥，数据不保存。它不能替代在 Chrome 中加载扩展。

E2E 在隔离的临时用户资料和无头 Chromium 中加载实际扩展，使用公开的 RFC 测试密钥及本地测试页面，不操作日常浏览器或真实账号。测试副本预授权本地站点，并以 `<all_urls>` 提供截图能力，代替无法在无头模式点击的原生右键菜单授权；正式包不包含这些固定权限。测试不覆盖真实权限对话框、原生菜单点击或真实跨设备传送。`preview` 只供内置浏览器视觉检查，不是扩展运行环境，演示代码不会打包进扩展。

## 自动填充与权限

默认没有任何站点读取权限。只有点击「启用填充」才申请当前站点的可选权限；可在设置中移除。站点精确匹配，不以服务名、邮箱域名、后缀或任意子域猜测网站。相同站点多个账号时，必须唯一匹配用户名。用户名只暂存在 `storage.session`，同源、同标签页有效期 10 分钟。跨源 iframe 不返回验证码。

不能访问 Chrome 内置页面、商店页面或封闭 Shadow DOM。网页控件没有统一标准，特殊自定义组件可能需要手动复制。无用户名时默认不自动填充；可对单个账号启用回退规则。只填写 TOTP，不支持 HOTP、短信接码、推送批准或 passkey。

`storage` / `unlimitedStorage` 用于本地账号库；`activeTab` 用于用户右键发起的截图；`scripting` 用于授权网站内容脚本；`contextMenus` 用于扫描入口；`clipboardWrite` 用于复制验证码。无固定全站访问权限，无外部网络请求代码。QR 解析库 jsQR 随包提供，许可证随包附带。

## 数据和同步边界

本地账号库以明文存于 Chrome 本地扩展存储，访问级别限制为 `TRUSTED_CONTEXTS`，内容脚本只能向 worker 申请当前匹配账号的一次性验证码。扩展本地页面可读账号库以生成列表。设备或浏览器资料已被控制时，本扩展不能保护本地密钥。不提供额外的本地保险库口令锁。

同步使用 Chrome 账号本身的同步设施，没有自建后端。解锁后的派生密钥只保存在受限的 `storage.session`，浏览器退出或扩展重载后丢失。`storage.sync` 只包含加密 envelope、分块和版本/时间元数据。**同步采用手动上传 / 拉取快照，不是后台自动双向实时同步**。拉取和备份恢复均保留本地数据、跳过相同用户名/密钥/算法/位数/周期的重复账号；既有账号元数据以本地为准，不传播删除。云端新快照会阻止基于旧版本上传，需先拉取核对。

Chrome Sync 总配额 102,400 字节，每项 8,192 字节；实现按 6,000 字符分块，并在 95 KB 前阻止上传。此限制只影响同步，本地账号不设产品数量上限，仍受设备空间限制。相同的公开 manifest key 固定扩展 ID，使不同路径安装可以使用同一同步命名空间；新设备仍需手动安装并开启 Chrome 的扩展同步。实际跨设备传送依赖 Google 服务及浏览器策略，自动化测试不连接真实同步账号。

所有导入先完成格式验证，再提交本地存储。Google 迁移不支持的算法、HOTP 或不完整批次会显示错误，不静默丢弃账号。加密备份只支持本项目公开的 v1 格式；不声称兼容原付费扩展的未公开加密格式。

## 验证

`npm test` 验证 RFC 6238 全部算法向量、密钥校验、迁移批次/损坏数据、加密往返/篡改/错误口令、精确主机与用户名匹配、同步配额和分块。`npm run test:e2e` 验证实际 MV3 worker、账号管理、扫码、备份恢复、同步加密存储和本地登录表单填充。测试仅使用公开测试数据，不记录真实密钥、口令、账号库或配置。
