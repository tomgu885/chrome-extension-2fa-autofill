# 本地验证器 · Local Authenticator

在 Chrome 中管理 TOTP 两步验证码，支持自动填充、TOTP 设置链接导入和本地加密备份。账号与链接在本机处理，seed 及其密文不会由扩展上传。

**全部功能免费开放，无需注册、购买许可证或安装手机配套应用。通过 Chrome 开发者模式安装，无需 Chrome Web Store。** 本项目独立实现，不是原商店扩展的修改版。

## 安装

需要桌面版 **Chrome 120 或更新版本**。安装后，扩展在当前 Chrome 用户资料中保存账号。

### 方式一：使用已构建的安装包

**[下载最新正式版安装包（ZIP，无需登录 GitHub）](https://github.com/tomgu885/chrome-extension-2fa-autofill/releases/latest/download/local-authenticator.zip)** · [查看最新正式版](https://github.com/tomgu885/chrome-extension-2fa-autofill/releases/latest)

安装包通过 GitHub Releases 提供，无需在本机安装 Node.js 或 Git，也不受 Actions 构建产物 30 天保留期限制。上方直链自动跟随最新正式版。发布页面 **Assets** 同时提供 `local-authenticator.zip` 和带版本号的 ZIP，两者内容一致。不要选择自动生成的 **Source code (zip)** 或 **Source code (tar.gz)**，它们是需要构建的源码包。

下载后按以下步骤安装：

1. 将 `local-authenticator.zip` 安装包解压到一个准备长期保留的文件夹。
2. 在 Chrome 地址栏输入 `chrome://extensions` 并打开。
3. 打开右上角的「开发者模式」。
4. 点击「加载已解压的扩展程序」，选择解压后**直接包含 `manifest.json`** 的文件夹。
5. 点击 Chrome 工具栏的拼图图标，将「本地验证器」固定到工具栏。
6. 点击扩展图标，即可添加或导入账号。

请保留解压后的文件夹，Chrome 会从这里读取扩展文件。安装步骤的简版见 [INSTALL.md](INSTALL.md)。

### 方式二：从本仓库构建

如果只有仓库源码，需要先安装 **Node.js 22+（包含 npm）**。使用 Git 获取源码并构建：

```sh
git clone https://github.com/tomgu885/chrome-extension-2fa-autofill.git
cd chrome-extension-2fa-autofill
npm ci
npm run build
```

也可以在 GitHub 仓库点击 **Code → Download ZIP** 下载源码，解压后在包含 `package.json` 的目录打开终端，执行 `npm ci` 和 `npm run build`。

构建成功后，按方式一的第 2–5 步操作，但加载的文件夹应为仓库内的 **`dist/`**。仓库根目录和 `src/` 不是可直接加载的安装目录。

如需生成可分发的安装包：

```sh
npm run package
```

输出文件为 `artifacts/local-authenticator-<版本号>.zip`，版本号取自 `package.json`。**GitHub 的 Download ZIP 是源码包，与这个已构建安装包不同；源码需要构建后才能安装。** 打包命令需要系统提供 `zip`；没有该命令时仍可直接加载 `dist/`，或手动压缩其中的文件。

## 使用

### 1. 添加第一个账号

1. 在需要启用两步验证的网站，进入安全设置，选择「身份验证器应用」或类似选项。
2. 在网站提供 TOTP 设置链接或 Base32 设置密钥时，打开本扩展。
3. 点击「＋ 添加」，填写以下信息后点击「保存账号」。

| 字段 | 如何填写 |
| --- | --- |
| 服务名称 | 方便识别的名称，例如 `GitHub`。 |
| 用户名 / 邮箱 | 实际登录用户名或邮箱；自动填充会使用它来匹配账号。 |
| TOTP 密钥 | 网站提供的 Base32 设置密钥，不是登录密码或当前的 6 位验证码。 |
| 登录网站 | 实际出现验证码输入框的完整主机名，例如 `github.com`；多个主机名用逗号分隔。 |
| 文件夹、标签 | 可选，用于区分个人、工作或不同客户的账号。 |

多数网站使用默认的 SHA1、6 位、30 秒周期；只有网站明确提供其他参数时，才调整「高级 TOTP 参数」。

保存后，点击账号卡片上的验证码即可复制，并粘贴到网站完成两步验证设置。网站提供的恢复码也应另行妥善保存。

### 2. 从 TOTP 设置链接导入

1. 打开扩展的「导入」页。
2. 将完整的 `otpauth://totp/…` 链接粘贴到「账号设置链接」，多个 TOTP 链接每行一条。
3. 点击「读取链接」，核对预览中的服务名称和用户名。
4. 按需填写文件夹及登录网站，点击「确认导入」。

支持以下格式（将 `<BASE32密钥>` 替换为网站提供的实际设置密钥）：

```text
otpauth://totp/MyAdmin:admin?secret=<BASE32密钥>&issuer=MyAdmin
```

此格式会识别服务 `MyAdmin` 和用户名 `admin`，未指定高级参数时使用 SHA1、6 位、30 秒周期。读取链接只在本机解析文本，不会打开链接或向网站发送请求。

也保留 Google Authenticator 的 `otpauth-migration://offline?data=…` **文本迁移链接**。一个迁移批次有多份链接时，逐份粘贴并读取，全部齐全后才能确认导入。导入会保留已有账号并跳过重复项。

二维码图片上传、网页右键扫码及截图识别已移除。若网站只提供二维码，请使用网站的手动设置方式取得 Base32 密钥，再通过「＋ 添加」填写。链接含有账号密钥，请勿公开分享。

### 3. 开启自动填充

自动填充需要同时完成**账号网站配置**和**网站授权**：

1. 在账号卡片点击「编辑」，在「登录网站」填写验证码页面的完整主机名。
2. 在 Chrome 中打开该网站，通过工具栏图标打开扩展。
3. 确认「当前网站」显示正确，点击「启用填充」，接受 Chrome 的该站点权限提示。
4. 在「设置」中确认「自动填充验证码」已开启，然后回到网站登录。
5. 页面出现验证码输入框且账号唯一匹配时，扩展会自动填入验证码。你仍需自行点击网站的登录/验证按钮。

例如：验证码页面为 `https://login.example.com/verify`，账号的登录网站填写 `login.example.com`，用户名填写实际登录时的用户名。不要填写整个 URL、邮箱域名、通配符或仅填写 `example.com` 来代替子域名。

默认同时匹配主机名和用户名。同一网站配置多个账号时，扩展不会随意选择。对于同源、同标签页的分步登录，扩展会临时记住前一步输入的用户名，最长 10 分钟。

如果验证码页面确实没有可识别的用户名，可编辑对应账号，显式勾选「页面无用户名时，允许单账号匹配填充」。仍然存在多个候选账号时不会填充。扩展不覆盖手动输入的内容；无法匹配时可以点击卡片复制验证码。

### 4. 整理账号

- 搜索框可搜索服务名称、用户名、文件夹、标签或网站；按 `/` 可快速聚焦搜索框。
- 编辑账号填写文件夹后，账号列表上方会出现对应筛选按钮。
- 点击卡片上的星标可置顶；点击「★ 置顶」可只查看置顶账号。
- 点击「编辑」修改账号；点击「删除」并确认后移除账号。
- 点击扩展右上角的 `↗`，可在独立标签页中使用完整管理界面。

### 5. 导出和恢复加密备份

**导出：**

1. 打开「本地备份」。
2. 在「加密备份」中输入至少 12 个字符的独立口令，再次输入确认。
3. 点击「导出加密备份」，保存下载的 JSON 文件。

**恢复：**

1. 在同一页的「恢复已有备份」区域选择加密 JSON 文件。
2. 输入导出时使用的备份口令。
3. 点击「解密并合并账号」。

恢复会保留本地账号并跳过重复项，既有账号的文件夹等信息以本地为准。口令错误或文件损坏时不会写入账号。口令无法找回；备份仅支持本项目的 v1 格式，不保证兼容其他验证器的加密备份文件。

### 6. 在设备间迁移账号

在原设备通过「本地备份」导出加密 JSON，将文件自行传输到新设备，再使用同一备份口令解密并合并账号。整个导出/恢复过程在各设备本机完成，扩展不上传文件，也不提供云同步。

### 7. 更新扩展

1. 先导出加密备份。
2. 源码安装时，在仓库目录执行 `git pull --ff-only`、`npm ci` 和 `npm run build`；安装包安装时，将新版文件覆盖到原来的解压目录。
3. 打开 `chrome://extensions`，点击本扩展卡片上的重新加载按钮。
4. 刷新需要自动填充的网站。

保持原来的安装目录，不必先卸载扩展。卸载会移除该 Chrome 用户资料中的本地账号；换电脑或切换用户资料时，请通过本地加密备份迁移。

**v1.0.2 升级说明：** 已移除 Chrome 云同步的全部代码、后台消息和界面入口；新版不再读取或写入 Chrome 云同步存储。本地账号、原有 v1 格式加密备份仍可使用。旧版本已上传的云端密文不会因升级自动删除；其他仍使用旧版本的设备也应升级。本次变更不会替用户删除历史云端副本。

## 常见问题

| 问题 | 处理方式 |
| --- | --- |
| 加载时提示找不到或无法读取 manifest | 安装包应选择直接包含 `manifest.json` 的文件夹；源码应先构建，再选择 `dist/`。不要直接选择 ZIP。 |
| 从 GitHub 下载后没有 `dist/` | GitHub 的源码包不含构建产物，请按方式二执行 `npm ci` 和 `npm run build`。 |
| 「启用填充」按钮不可用 | 在普通 HTTP/HTTPS 登录网站中，从工具栏打开扩展；Chrome 内置页面和扩展自身管理页不能作为授权目标。 |
| 已授权，仍未填充 | 检查「设置」开关、验证码页面的精确主机名、用户名及是否有多个候选账号；刷新网站后重试。特殊自定义控件可手动复制。 |
| 网站提示验证码错误 | 检查电脑日期、时间和时区设置，确认密钥、算法、位数、周期与网站一致，并使用当前有效的验证码。 |
| 链接无法读取 | 请粘贴完整的 `otpauth://totp/…` 或 Google 文本迁移链接；普通 HTTP 网页链接和 HOTP 不受支持。 |
| 忘记备份口令 | 无法找回口令。若本地账号仍可访问，可使用新口令重新导出备份。 |

## 隐私与数据

- 验证码在本机生成，无遥测、广告、账号注册或许可证校验；没有自建后端或远程代码。
- **本地密钥以明文保存在 Chrome 本地扩展存储中，不另设本地口令锁。** 加密保护适用于导出的本地备份文件。请保管好设备和浏览器用户资料。
- 站点访问按需授权，可到「设置 → 已授权的网站」移除权限。
- 本地备份使用 AES-256-GCM 和口令派生密钥；seed、备份密文和口令不会由扩展上传。
- v1.0.2 起不使用 Chrome 云同步存储；运行代码不调用网络请求 API，扩展页面和后台的 CSP 为 `connect-src 'none'`。自动填充只将一次性验证码交给目标网页，不把 seed 交给网页。
- **卸载扩展前请先备份。** 本地账号不会自动存到其他 Chrome 用户资料或其他设备中。

## 功能

- 不设账号数量上限；生成和复制 SHA1 / SHA256 / SHA512、6 / 8 位 TOTP；支持 5–300 秒周期。
- 增删改账号；搜索、文件夹、标签、置顶。
- 本地解析 `otpauth://totp` 设置链接和 Google Authenticator protobuf 文本迁移链接，支持多份迁移批次完整性检查、预览和去重。
- 按完整主机名和用户名自动匹配，识别动态表单和分格验证码；支持同源分步登录的临时用户名记忆。不自动提交、不覆盖手动输入。默认禁用无用户名匹配，可按账号开启。
- AES-256-GCM 加密备份、导入合并。PBKDF2-SHA256 / 600,000 次迭代，随机 16 字节盐及 12 字节 IV。

## 自动填充与权限

默认没有任何站点读取权限。只有点击「启用填充」才申请当前站点的可选权限；可在设置中移除。站点精确匹配，不以服务名、邮箱域名、后缀或任意子域猜测网站。相同站点多个账号时，必须唯一匹配用户名。用户名只暂存在 `storage.session`，同源、同标签页有效期 10 分钟。跨源 iframe 不返回验证码。

不能访问 Chrome 内置页面、商店页面或封闭 Shadow DOM。网页控件没有统一标准，特殊自定义组件可能需要手动复制。无用户名时默认不自动填充；可对单个账号启用回退规则。只填写 TOTP，不支持 HOTP、短信接码、推送批准或 passkey。

`storage` / `unlimitedStorage` 用于本地账号库；`activeTab` 用于从工具栏打开扩展时识别当前网站；`scripting` 用于授权网站内容脚本；`clipboardWrite` 用于复制验证码。无固定全站访问权限，无外部网络请求代码。不包含图片识别或二维码解析库。

## 本地数据与备份边界

本地账号库以明文存于 Chrome 本地扩展存储，访问级别限制为 `TRUSTED_CONTEXTS`，内容脚本只能向 worker 申请当前匹配账号的一次性验证码。扩展本地页面可读账号库以生成列表。设备或浏览器资料已被控制时，本扩展不能保护本地密钥。不提供额外的本地保险库口令锁。

账号库只写入 Chrome 本地扩展存储，临时用户名只写入会话存储，不使用 Chrome 云同步。TOTP 设置链接只作为本地文本数据解析。扩展没有自建服务端、在线扫码服务或遥测接口，运行不需要联网；网站登录本身及 GitHub 安装包下载仍由浏览器联网处理。

本地加密备份保留 v1 文件格式：在本机执行 PBKDF2-SHA256 / 600,000 次口令派生和 AES-256-GCM 加密，下载 JSON 文件；恢复也在本机完成。加密后的账号库不会上传，备份口令和派生密钥也不会上传。备份恢复会保留本地账号，跳过相同用户名/密钥/算法/位数/周期的重复账号，已有账号信息以本地为准。

相同的公开 manifest key 保持扩展 ID，便于在同一路径重新加载新版时保留本地数据。新设备需手动安装扩展，并使用加密备份文件迁移账号。本地账号不设产品数量上限，仍受设备存储空间限制。

所有导入先完成格式验证，再提交本地存储。Google 迁移不支持的算法、HOTP 或不完整批次会显示错误，不静默丢弃账号。加密备份只支持本项目公开的 v1 格式；不声称兼容原付费扩展的未公开加密格式。
